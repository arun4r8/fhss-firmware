RF Packets (updated 11-15)

Pod → ground: telemetry frame (one per packet, 2 every 400 ms hop)

Radio Header (6 bytes)Embedded Control (78 bytes)

NetworkFlagsHOP Bits Frame Header4 bits layout version + 4 bits frame counter Pod State (new)4 bits state + 4 bits spare Readings38 sensors × 16 bits, fixed order, no tags
  • 84 bytes on air = 149 ms (SF7 / 125 kHz). The state byte added no airtime.
  • All 38 sensors in every packet: no CAN message header or per-sensor tags needed, because both ends share the sensor order. A reading of 0xFFFF = sensor fault / no data yet.
  • Layout version (now 2) changes whenever the sensor list or order changes, so an out-of-date ground rejects frames instead of mislabelling them.

  • 10 bytes on air = 42 ms, sent every hop; a lost command is repeated on the next hop.
  • The pod forwards the target state to the VCU on CAN and reports the state in its next frame. On hardware the ground saw a new state confirmed in 0.3–0.5 s.
